## 3. Findings

### Medium

**[M-2] Non-string body fields returned 500 instead of 400 (5 routes)** — FIXED
(`fix(api): reject non-string body fields with 400 instead of 500`, commit `a27d338`)

- **Description:** Session 1's M-1 fixed the *unparseable* body case. This is
  the next layer: a syntactically valid body with wrong **field types**.
  `{"password": 123}` passed `!password` (truthy) and both length checks
  (`(123).length` is `undefined`; `undefined < 6` is `false`), then threw in
  `bcrypt.hash` → 500. Same shape in `change-password` (`.length` / `compare`),
  `comments` POST (`content.trim` is not a function), `videos` POST
  (`channelId`/`thumbnailUrl`/`aspectRatio`/`categoryIds` flowing typed-wrong
  into Prisma), and `videos/[id]` PATCH (`title`/`description`/`thumbnailUrl`).
- **Impact:** Client-input errors surfaced as server faults (noisy in
  monitoring, misleading to API consumers). No security impact.
- **Fix:** `typeof !== 'string'` guards returning descriptive 400s —
  extending the exact pattern `playlists` POST already used (it was the only
  body-taking route already guarded). `categoryIds` gets `Array.isArray` +
  element-type check. Also simplified videos PATCH's
  `title: trimmedTitle ?? body.title` fallback, which existed only to forward
  the now-rejected non-string case to Prisma.
- **Verification:** live against `next dev`: `register` with
  `{"password": 123}` → `400 {"error":"Password must be a string"}` (was 500);
  short string password still → `400` length message (no regression).
  Authenticated routes (comments, change-password, videos) carry the identical
  guard and pass typecheck; runtime testing blocked by the local DB being down
  (§5). DEVLOG entry added; not in public CHANGELOG per ADR-1.

### Low

**[L-2] seed/cleanup-demo direct PrismaClient** — FIXED, backlog item checked off
(`refactor(db): route seed/cleanup-demo through shared Prisma singleton`, commit `59f23da`)

Both ops endpoints now import the shared `db` singleton (serverless pool
params apply); `finally { $disconnect() }` blocks removed — the singleton
must stay connected. Smoke-tested: both endpoints respond `401` without a
key (key gate runs before any DB access).

### Nice to have (not fixed — noted only)

- **[N-1] Invalid `categoryIds` values (well-typed but nonexistent ids) in
  `videos` POST** cause a Prisma FK violation → 500. Type guards now catch
  wrong *types*; wrong *values* would need an existence check or
  `PrismaClientKnownRequestError` mapping. Rare path (UI sends real ids).
- **[N-2] Body validation is per-route and hand-rolled.** A schema layer
  (e.g. zod per route) would eliminate this bug class wholesale.
  Architectural — flagged, not implemented (per findings-handling policy).
