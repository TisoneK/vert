## Findings

### [HIGH] Dependency vulnerabilities — 30 (1 critical) — FIXED in 0.9.1
- `next-auth` 4.24.14 carried a **critical** email-normalizer bypass
  (GHSA-7rqj-j65f-68wh) plus a high (`getToken()` uncaught exception) and a
  moderate. This is (part of) the high dependabot alert Session 45 flagged.
- `next` 16.2.9: 9 advisories (SSRF in rewrites, middleware bypass w/
  Turbopack, Server Actions DoS, cache-confusion family, image-optimizer DoS).
- `sharp` 0.34.5: inherited libvips CVEs (high). Direct dep, but nothing in
  `src/` imports it — used by the image-optimizer path.
- Transitive highs: `js-yaml` (quadratic CPU, via mdxeditor/eslint),
  `nanoid` (insecure generators, via postcss), `postcss` (source-map path
  traversal); moderates: `undici` ×3 via @vercel/blob, plus lodash family.
- **Fix:** bumps to next ^16.2.11 (resolved 16.3.4), next-auth ^4.24.15,
  sharp ^0.35.0 (resolved 0.35.4); overrides js-yaml ^4.3.0, nanoid ^3.3.16,
  postcss ^8.5.23, undici ^6.28.0. Commits `42040f7` (build) + `4c93773`
  (security), tag `v0.9.1`, pushed.

### [MEDIUM] Remaining 8 audit findings — not actionable, tracked
- `lodash`/`lodash-es` (high + moderates): no patched release exists
  (advisory range ends at the current latest). App never calls the affected
  APIs (`_.template`, `_.unset`, `_.omit`); lodash arrives via
  recharts/@reactuses/core on non-attacker-controlled data. Re-check when
  upstream releases a fix.
- `deepmerge-ts` (<8.0.0, major fix) + `defu` (<=6.1.4): Prisma CLI chain —
  dev/build-time only, no runtime request surface. Don't override a major
  inside the Prisma toolchain; wait for Prisma.
- Note: GitHub's dependabot banner may continue to show "1 high" until its
  manifest re-scan catches up / for the unpatched lodash advisory.

### [MEDIUM] Build script not cross-platform — FIXED (`42040f7`)
- `build` ended with `cp -r` steps for the standalone output; Windows rejects
  them, so local production builds died after the (successful) Next compile.
- Replaced with `scripts/standalone-copy.mjs` (`fs.cpSync`) — identical
  behavior on Linux/Vercel, works on Windows. Full `bun run build` now passes
  locally end-to-end. This also makes the `integration` gate in gates.conf
  (`bun run build`) actually runnable on this machine.

### [LOW] Local env trap on this machine (documented, not a repo bug)
- `.env.local` (Vercel CLI pull) had `NEXTAUTH_URL=""` and `NEXTAUTH_SECRET=""`
  as empty strings; next-auth module init parses the empty string as an
  invalid URL and the build's prerender pass dies with `ERR_INVALID_URL`
  (import chain: layout → VertApp → next-auth/react). Other machines had the
  vars simply unset, which falls back cleanly — that's why it never surfaced.
  Fixed locally with real dev values; documented in DEVLOG + environments.md.

### [LOW] Lint warnings 16 → 3 — FIXED (`d9bea7d`)
- Removed 5 unused imports, an unused empty-state prop (plus its 2 call-site
  args), an unused OAuth-heuristic variable, renamed/removed 2 unused
  function params, and deleted 3 stale `set-state-in-effect` eslint-disable
  directives that no longer suppress anything.
- Remaining 3 are deliberate: AdminDashboard `exhaustive-deps` ×2 (adding
  those deps without a refetch design would loop; needs a deliberate fix),
  and the vendored shadcn `use-toast` ActionType warning.

### Reviewed-clean areas (no action)
- Security surfaces: contact route (validation + rate limit + no error
  leakage), upload route (auth + content-type allowlist + client token),
  rate-limit lib, register/login policies (min 8 + blocklist from 0.7.3),

  key-gated, prod-disabled), changelog HTML escaping (inline parser escapes

- Architecture/UX/perf: the S33/S40 audit backlog accurately reflects what
  remains (infra-blocked M2/M3/email/breach-check; design-deferred L2/L6/L8/
  L9/L11, P2/P4/P5; content realism). Nothing new to add — didn't re-report.
